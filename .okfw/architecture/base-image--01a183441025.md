# Base image

The templates build on the base image `trusted/fedora43-minimal` from `ghcr.io/infrashift/trusted-base-images`. The `FROM` line of `shared/Containerfile` pins the image by digest (ADR-007).

| Platforms | `linux/amd64`, `linux/arm64` |

The `trusted-base-images` repository signs and attests the base image. The templates use the digest, not a tag. To change the pin, edit `shared/Containerfile`, then copy it to all managed copies. See [Shared Containerfile](/architecture/shared-containerfile--01a183447e12.md).

## What the minimal image does not have

`fedora43-minimal` is the only Fedora variant in the trusted namespace. There is no `fedora43-standard`.

The image ships `bash`, `curl-minimal`, `useradd`, `dnf5` and coreutils. It does not ship these tools:

* `tar`, `gzip`, `xz`
* `su`, `runuser`, `sudo`
* `python3`
* `gpg`

Features need `tar`, `gzip`, `curl` and `runuser`. The shared Containerfile installs them. Ansible needs a Python interpreter. The bootstrap feature supplies a pinned Python, because the image has no `python3`. See [Bootstrap contract](/architecture/bootstrap-contract--01a18344b8d3.md).

## Sources of these facts

* The list of missing tools comes from ADR-007, which inspected the image layer.
* The comments in `shared/Containerfile` and the `CLAUDE.md` file give the same list.

## Analysis

* ADR-007 names the Fedora 43 end of life as the main risk. The base image must move to Fedora 44 or later on the Fedora schedule.
* The Fedora base has more CVE churn than UBI 9. The base pin changes more frequently because of this.
* ADR-007 still shows the first Fedora digest, `sha256:1ed67eb14da5…`. The ADR records the decision, not the current pin. Read the current pin from `shared/Containerfile`.
